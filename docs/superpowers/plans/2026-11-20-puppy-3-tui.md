# puppy Plan 3 — Full-screen dashboard (TUI)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `puppy` (no arguments) opens a polished, btop/lazygit-style full-screen dashboard that talks to the daemon: live download list with smooth progress bars, a detail pane with speed graph and per-connection segment strip (HTTP) or piece map (torrent), a footer with global stats and context-sensitive hotkey hints, popups for add / limits / delete / help, filtering, mouse support, and a light/dark-aware theme.

**Architecture:** New library crate `puppy-tui`. A pure `App` state machine (no I/O) receives `Msg`s (key/mouse/paste/resize, daemon events, command results, ticks) and returns `Cmd`s (daemon requests, quit). Rendering is a pure function `ui::draw(&App, &mut Frame)`. A thin async runtime loop (`run`) bridges crossterm's `EventStream`, the `puppy-client` event stream and a tick timer into `Msg`s, executes `Cmd`s through a `DaemonApi` trait (implemented for `puppy_client::Client`, faked in tests), and owns terminal setup/teardown. This makes nearly everything testable with ratatui's `TestBackend` and plain unit tests.

**Tech Stack:** ratatui 0.30 (default features, crossterm backend), crossterm 0.29 (`event-stream`, default `bracketed-paste`), tokio, futures-util, async-trait, puppy-proto, puppy-client, puppy-core types.

**Spec:** `docs/superpowers/specs/2026-11-19-puppy-design.md` → "TUI dashboard" section (layout mock, behaviours). The user explicitly wants: full-screen dashboard (not prompt-style), "CLI-modern" polish — nicely rendered progress, speeds, segments — and hotkeys described at the bottom.

**Builds on:** Plan 2 (`plan-2-daemon`): `puppy_client::Client` (`connect_or_spawn`, `call`, `add`, `list`, `subscribe`, `next_event`, `is_connected`), protocol types in `puppy_proto` (`Request`, `ReplyData`, `Event::{Snapshot, Added, Completed, Failed, Removed, NeedsAttention, Unknown}`, `DownloadSnapshot`, `Totals`, `Settings`, `EngineKindTag`), `puppy_core::types::{DownloadState, AttentionReason, EngineDetail, SegmentView, AddRequest, Source, RequestContext}`, and the `puppy` binary (`crates/puppy/src/main.rs`, currently prints a one-line summary when run without args).

## Global Constraints

- Cross-platform terminals: Linux/macOS terminals, Windows Terminal and legacy conhost. Use only crossterm features available on all three. Must restore the terminal (leave alternate screen, disable raw mode, mouse capture, bracketed paste, show cursor) on normal exit, on error, and on panic (panic hook).
- Minimum usable size **80×24**. Below **60×16** render a single centered message "puppy needs a bigger terminal (60×16)". Wide layout (detail pane to the right) when width ≥ **110**; otherwise the detail pane goes below the list.
- Colors: semantic palette tokens only (no ad-hoc colors in widgets). Two palettes: `dark` and `light`; config `theme = "auto" | "dark" | "light"` (auto ⇒ env `COLORFGBG` if present — background digit 0–6 or 8 ⇒ dark, 7 or 9–15 ⇒ light — else dark). If `NO_COLOR` is set ⇒ monochrome (modifiers only: bold/dim/reversed). If `COLORTERM` is not `truecolor`/`24bit` ⇒ map palette to the 16 ANSI colors.
- Redraw on every received snapshot and on input; no busy loop. Target ≤ 30 fps; coalesce bursts.
- Never block the UI on a daemon call: every `Cmd` executes on a spawned task and reports back via `Msg::CmdResult`.
- Formatting: sizes in binary units with one decimal (`1.5 GiB`, `812.0 KiB`, `0 B`); speeds use the same binary units with `/s` (`11.4 MiB/s`) for consistency; ETA `0:41`, `12:05`, `1:02:03`, `—` when unknown.
- Keyboard map (exact): `j`/`↓` down, `k`/`↑` up, `g`/`Home` top, `G`/`End` bottom, `a` add, `p` pause, `r` resume, `d`/`Delete` delete (confirm), `R` restart (Failed/NeedsAttention only), `l` per-download limit, `L` global limits, `+`/`-` max active ±1, `Shift+↑`/`Shift+↓` (also `K`/`J`) move in queue, `/` filter, `Esc` close popup / clear filter, `?` help, `q`/`Ctrl+C` quit. Footer shows the subset valid for the current selection/mode.
- The TUI never exits the daemon; quitting only disconnects.

## Review Focus

1. **Daemon disappears mid-session** (killed, crashed, idle-exit race) → UI shows a "reconnecting…" banner, keeps the last list greyed, retries `connect_or_spawn` with backoff, and resumes seamlessly; it never panics or leaves the terminal broken. Test: Task 7 `reconnects_after_daemon_restart`.
2. **Terminal resize to tiny and back, while popups are open** → no panics (no negative-size rects, no index out of range), popups clamp to the screen. Test: Task 4 `render_never_panics_any_size` (property-style loop over sizes 1×1 … 200×60 for several App states).
3. **Very long names / paths / URLs, non-ASCII and wide (CJK/emoji) characters** → truncated with `…` by display width (unicode-width), never splitting a grapheme or overflowing a cell. Test: Task 1 `truncate_by_display_width`, Task 4 `long_cjk_name_fits`.
4. **Hundreds of downloads** → list scrolls with the selection kept visible; rendering stays fast (< 5 ms for 500 rows in release). Test: Task 4 `selection_stays_visible_when_scrolling`, Task 2 `selection_follows_id_across_snapshots`.
5. **Pasting a multi-line blob / huge text into the add popup** → only the first line is used for the URL (rest ignored), input capped at 8 KiB, invalid sources show an inline error instead of sending. Test: Task 5 `paste_multiline_takes_first_line`, `invalid_source_inline_error`.

### Task 7: Runtime — terminal, event loop, daemon API, reconnect

**Files:** `src/api.rs`, `src/runtime.rs`, `tests/runtime.rs`.

**Interfaces — Produces:**
```rust
#[async_trait] pub trait DaemonApi: Send + Sync + 'static {
    async fn connect(&self) -> Result<(Settings, Vec<DownloadSnapshot>), String>;   // (re)connect + hello + GetSettings + List + Subscribe(250)
    async fn next_event(&self) -> Option<Event>;                                     // None ⇒ disconnected
    async fn exec(&self, cmd: Cmd) -> Result<Option<Msg>, String>;                    // FetchDetail ⇒ Some(Msg::Detail); others ⇒ None
}
pub struct ClientApi { /* SocketName, exe path, Mutex<Option<puppy_client::Client>> */ }
impl ClientApi { pub fn new(socket: SocketName, exe: PathBuf) -> Self; }   // connect uses Client::connect_or_spawn
pub async fn run(api: Arc<dyn DaemonApi>, theme: Theme) -> anyhow::Result<()>;          // real terminal
pub async fn run_with<B: Backend>(api: Arc<dyn DaemonApi>, theme: Theme, terminal: &mut Terminal<B>,
```

Loop: `select!` over input stream, daemon events (`api.next_event()` in a dedicated task forwarding into an mpsc), command results (mpsc from spawned exec tasks), a 500 ms tick, and a redraw throttle (draw at most every 33 ms when dirty).
