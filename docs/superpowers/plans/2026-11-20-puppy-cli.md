# puppy CLI commands Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scriptable `puppy` subcommands (add, ls, info, pause/resume/restart, rm, move, limit, max-active, wait, watch, stop) with human output, `--json`, and stable exit codes.

**Architecture:** All new code lives in `crates/puppy`. `main.rs` keeps clap parsing and dispatch; each command family is a small module that talks to the daemon through `puppy_client::Client` and renders via a shared `output` module. Formatting and source/rate parsing reuse `puppy_tui::format` and `puppy_tui::app::forms::parse_source` (the binary already depends on puppy-tui).

**Tech Stack:** clap 4 (derive), tokio, puppy-client, puppy-proto, puppy-daemon (`Paths`), puppy-tui (format/parse helpers), serde_json.

**Spec:** `docs/superpowers/specs/2026-11-20-puppy-cli-design.md`

## Global Constraints

- Exit codes exactly: `0` ok · `1` error (daemon/operation) · `2` usage · `3` unknown id · `4` waited download failed · `5` waited download needs attention. Multiple ids/outcomes ⇒ the highest code wins.
- Every command accepts `--json` (global flag). JSON = protocol types serialized as-is (`DownloadSnapshot`, `EngineDetail`, `Settings`, `Event`); `watch --json` is NDJSON (one event per line).
- Human output → stdout; progress lines and errors → stderr. No progress lines when stderr is not a TTY.
- Every command uses `Client::connect_or_spawn(&paths, "puppy-cli", &exe, &[])` except `stop` (plain `connect`; not running ⇒ print "puppy is not running", exit 0).
- RATE parsing via `puppy_tui::format::parse_rate`; sources via `puppy_tui::app::forms::parse_source` (move/expose it as `pub` if needed — no duplication).
- Local verification only: `cargo test --workspace`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`. Never trigger GitHub Actions.

## Review Focus

1. **Stdin source list with blank lines, comments, CRLF and surrounding quotes** (`puppy add -` fed from a file written on Windows) → blank and `#` lines skipped, CRLF/quotes trimmed, each valid source added, invalid ones reported individually without aborting the rest; exit code 1 if any failed. Test: Task 2 `add_stdin_mixed_lines`.
2. **Piping output into `head`/`grep` that closes early** (`puppy ls | head -1`, `puppy watch | head`) → exits quietly (no panic, no "Broken pipe" noise), exit 0. Test: Task 1 `stdout_broken_pipe_is_quiet`.
3. **Ids that don't exist or aren't numbers** (`puppy pause 99`, `puppy rm abc`) → per-id message on stderr, exit 3 (unknown) / 2 (not a number), other valid ids in the same command still processed. Test: Task 3 `mixed_valid_and_unknown_ids`.
4. **`wait` on a download that's already finished, failed, or removed meanwhile** → returns immediately with the right code (0 / 4 / 3), never hangs. Test: Task 4 `wait_already_terminal_states`.
5. **Long names / non-ASCII in `ls` tables** → columns stay aligned by display width; names truncated with `…`; `--json` keeps full names. Test: Task 2 `ls_table_aligns_wide_names`.

### Task 1: CLI skeleton, errors, output plumbing

**Files:** Create `src/cli/{mod.rs, output.rs}`; Modify `src/main.rs`; Create `tests/common/mod.rs` (move `Env` and helpers out of `tests/e2e.rs`, which then uses `mod common;`); Create `tests/cli.rs`.

**Interfaces — Produces:**
```rust
pub struct Ctx { pub paths: Paths, pub exe: PathBuf, pub json: bool }
impl Ctx { pub fn from_env(json: bool) -> anyhow::Result<Self>;
           pub async fn client(&self) -> Result<Client, CliError>; /* connect_or_spawn */ }
#[derive(Debug, thiserror::Error)]
pub enum CliError { #[error("{0}")] Usage(String), #[error("{0}")] UnknownId(String),
    #[error("{0}")] Failed(String) /*waited download failed*/, #[error("{0}")] Attention(String),
    #[error(transparent)] Other(#[from] anyhow::Error) }
impl CliError { pub fn exit_code(&self) -> u8; } // 2,3,4,5,1
pub fn worst(codes: impl IntoIterator<Item = u8>) -> u8;        // max
// output.rs
pub fn out(line: impl Display);  pub fn err(line: impl Display);  // ignore EPIPE: on BrokenPipe exit(0) quietly
pub fn json<T: Serialize>(v: &T);                                 // one line
pub fn table(headers: &[&str], rows: &[Vec<String>], widths: &[ColWidth]); // display-width aligned, truncation with '…'
pub enum ColWidth { Fixed(usize), Flex /*takes remaining terminal width (COLUMNS or 100)*/ }
```
`main.rs`: global `--json` flag; existing `daemon`, `status`, dashboard (no args), `--theme` unchanged. Map `Result<(), CliError>` to `ExitCode`. Also set `SIGPIPE` handling so writes to a closed pipe return `BrokenPipe` (Rust default) and `out` exits 0 on it.

- [ ] **Step 2–4:** FAIL → implement → PASS (run `cargo test -p puppy --test cli --test e2e`).
- [ ] **Step 5:** Commit `feat(cli): command skeleton, exit codes, pipe-safe output`.

### Task 2: `add`, `ls`, `info`

**Files:** Create `src/cli/{add.rs, list.rs}`; Modify `src/main.rs`; tests in `tests/cli.rs`.

**Interfaces — Produces:** `pub async fn add(ctx: &Ctx, args: AddArgs) -> Result<Vec<DownloadId>, CliError>`; `pub async fn ls(ctx: &Ctx, states: Vec<StateFilter>) -> Result<(), CliError>`; `pub async fn info(ctx: &Ctx, id: DownloadId) -> Result<(), CliError>`.
`AddArgs { sources: Vec<String>, output_dir: Option<PathBuf>, name: Option<String>, paused: bool, limit: Option<String>, headers: Vec<String>, cookie: Option<String>, referer: Option<String> }` (Task 4 adds `wait: bool`). `--name` only valid with exactly one source (else Usage). `--header "K: V"` split at the first `:`, trimmed; malformed ⇒ Usage. Relative `-o` resolved against cwd. Source `-` reads stdin: skip blank and `#` lines, trim CRLF, whitespace and one pair of surrounding quotes.
Human output: `add` prints `added <id> <name-or-source>` per source; `ls` table columns `ID │ STATE │ PROGRESS │ SPEED │ ETA │ NAME` (state words: queued, starting, active, paused, done, failed, retrying, attention, unknown; progress `45%` or `—`); `info` prints key/value lines (name, path, source, state + reason, size, downloaded, speed, eta, limit, then HTTP segments count/active or torrent pieces/peers/ratio). `StateFilter` values: `queued,starting,active,paused,completed,failed,attention`.
JSON: `add` ⇒ `[{"id":..,"source":".."}]`; `ls` ⇒ array of `DownloadSnapshot`; `info` ⇒ `{"download": DownloadSnapshot, "detail": EngineDetail|null}`.
The `--wait` flag is not part of this task; Task 4 adds it.
- [ ] **Step 1: Failing tests:** `add_http_and_ls_shows_it` (puppy_testserver file; `puppy add --paused URL` ⇒ exit 0, stdout `added 1 …`; `puppy ls` contains `paused`; `puppy ls --json` parses to 1 snapshot); `add_stdin_mixed_lines` (stdin `"\r\n# c\n \"URL1\"\r\nnot a url\nURL2\n"` ⇒ 2 added, stderr names `not a url`, exit 1); `add_name_with_two_sources_is_usage` (exit 2); `add_headers_reach_server` (`--header "X-Test: 1" --cookie a=b --referer http://r/` ⇒ testserver `requests_seen` contains them); `ls_state_filter`; `ls_table_aligns_wide_names` (names `日本語ファイル名.iso` and 80-char ASCII; every row's display width equal; long name ends with `…`; `--json` has full name); `info_json_has_detail`.

### Task 3: Control commands

**Files:** Create `src/cli/control.rs`; Modify `src/main.rs`; tests in `tests/cli.rs`.

**Interfaces — Produces:** `pub async fn act(ctx: &Ctx, action: Action, targets: Targets) -> Result<(), CliError>` with `enum Action { Pause, Resume, Restart }`, `enum Targets { All, Ids(Vec<String>) }`; `rm(ctx, ids: Vec<String>, delete_files: bool)`; `move_to(ctx, id: String, position: usize)`; `limit(ctx, LimitArgs)` where `LimitArgs { id: Option<String>, rate: Option<String>, global: bool, down: Option<String>, up: Option<String> }` (`limit <ID> <RATE>` or `limit --global [--down] [--up]`; both forms mixed ⇒ Usage; `--global` with neither ⇒ print current global limits); `max_active(ctx, n: u16)` (0 ⇒ Usage); `stop(ctx)`.
Behaviour: ids parsed per item (non-numeric ⇒ message + code 2, continue); daemon `not_found` ⇒ code 3; `invalid_state` for an explicit id ⇒ message + code 1; with `all`, act only on downloads where the action is valid (pause: queued/starting/active; resume: paused/failed; restart: failed/attention) and print `nothing to <action>` when none. Human output per id: `paused 3`, `removed 4 (files deleted)` etc. JSON: `[{"id":3,"ok":true}|{"id":"abc","ok":false,"error":"…","code":2}]`. `stop` sends `Shutdown`, waits up to 10 s for the daemon to go away (connect fails), prints `stopped`.
- [ ] **Step 1: Failing tests:** `pause_resume_by_id`; `pause_all_skips_completed`; `mixed_valid_and_unknown_ids` (`puppy pause 1 99 abc` ⇒ 1 paused, exit 3 — highest of {0,3,2}; stderr names 99 and abc); `rm_delete_files_removes_file`; `move_reorders_queue` (max-active 1, three queued); `limit_per_download_and_global` (then `ls --json` shows limit; `puppy --json limit --global` shows settings); `max_active_zero_is_usage`; `stop_when_running_then_not_running` (second `stop` exit 0 with "not running").
- [ ] **Step 2–4:** FAIL → implement → PASS.
- [ ] **Step 5:** Commit `feat(cli): pause, resume, restart, rm, move, limit, max-active, stop`.

### Task 4: `wait`, `add --wait`, `watch`, README

**Files:** Create `src/cli/wait.rs`; Modify `src/cli/add.rs`, `src/main.rs`, `README.md`; tests in `tests/cli.rs`.

**Interfaces — Produces:** `pub async fn until_done(ctx: &Ctx, client: &mut Client, ids: &[DownloadId]) -> Result<(), CliError>`; `pub async fn wait(ctx, ids: Vec<String>)`; `pub async fn watch(ctx)`.
Behaviour: subscribe at 250 ms; check current snapshot first (already terminal ⇒ return immediately); terminal = Completed (0) / Failed non-transient (4) / NeedsAttention (5) / removed or unknown (3); a transient failure is NOT terminal (puppy retries) — keep waiting and show `retrying in m:ss`. Progress (stderr, TTY only): one line rewritten with `\r`: `⠋ 2/3 · 45% · 11.4 MiB/s · eta 0:41`. Ctrl-C while waiting ⇒ exit 130, downloads keep going. On daemon disconnect ⇒ error exit 1 "lost connection to puppy". `watch`: human lines `HH:MM:SS added 3 name` / `completed` / `failed: reason` / `needs attention: reason` (snapshots not printed); `--json` prints every Event as NDJSON including snapshots; ends on Ctrl-C (exit 0). README: a "Command line" section listing every command, `--json`, and the exit-code table.
