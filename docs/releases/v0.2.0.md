puppy 0.2.0 grows from an HTTP and BitTorrent downloader into a fuller download manager: FTP, FTPS and SFTP, Metalink, one download from several mirrors, checksum verification, input files, faster torrent restarts, shell completions and man pages, and static Linux builds that run anywhere.

## What's new

- **More protocols.** `ftp://`, `ftps://` (implicit TLS) and `ftpes://` (TLS required) downloads, segmented over several connections like HTTP. Plain `ftp://` tries TLS first and only goes on without it when the server refuses it; `[ftp] tls = "require"` or `"off"` changes that. `sftp://` downloads log in with your ssh-agent, then your default keys, then a password in the URL. Host keys are always checked against `~/.ssh/known_hosts` and puppy's own list; an unknown host is refused with its fingerprint, and `puppy ssh trust HOST` adds it.
- **Mirrors.** `puppy add URL --mirror URL2 --mirror URL3` spreads one download over several locations, which may mix HTTP, FTP and SFTP. A location that serves another size is dropped, one that fails hands its part to the others, and a resumed download checks every location on its own, so a changed file is still never silently continued.
- **Metalink.** `puppy add file.meta4`, or a `.meta4` / `.metalink` URL (`--metalink` for one without the extension), adds every file the metalink lists, with its mirrors, its strongest hash and its size. Names are checked hard: nothing is ever written outside the download folder.
- **Checksums.** `--checksum sha-256=…` (also md5, sha-1, sha-224, sha-384, sha-512) checks the finished file. A new *verifying* state shows the progress; a mismatch fails the download, keeps the file, and makes `puppy wait` exit with 4.
- **Input files.** `puppy add -i list.txt` (or `-i -`) reads an input-file format: one download per line, TAB-separated mirrors, and indented options such as `dir`, `out`, `checksum`, `header` and `select-file`. One bad entry rejects the whole file, so nothing is half-added.
- **Faster torrent restarts.** After a clean daemon stop, torrents carry on from the pieces they had instead of re-checking all their data. Anything doubtful (a file changed, cut short or rewritten, an unclean stop) still gets the full check.
- **Shell completions and man pages.** `puppy completions bash|zsh|fish|powershell|elvish`, and `man puppy` / `man puppy-add`. Both ship in the archives, and `install.sh` installs them for the shells it finds.
- **Static Linux builds.** New `x86_64` and `aarch64` `-musl` archives run on any Linux: older distributions, Alpine, minimal containers. `install.sh` picks them when the system has no glibc 2.35; `PUPPY_LIBC=musl` or `gnu` chooses by hand. An install keeps updating to its own kind.

## Changed

- **Redirects to another site carry less.** Following a redirect to another origin, puppy now drops your custom `-H` headers (except `Accept`, `Accept-Language` and `User-Agent`) and cuts the referer down to its origin, as browsers do; cookies and credentials were already dropped. This is stricter than curl: a header that a server needs after a redirect must be given with the final URL.
- **No passwords in resume files.** A password in a download's URL is no longer written to its resume file (`.part` sidecar); it stays in the daemon's private state file only.

## Upgrading

Your queue, settings and downloads carry over, and 0.1.x installs update to 0.2.0 by themselves. A 0.1.x daemon that is still running does not know the new options, and the command line notices: a download added with `--checksum` is taken back with a request to restart the daemon (`puppy stop`), and mirrors or a Metalink size that the old daemon dropped are warned about.

## Install

The quickest way:

```sh
curl -fsSL https://raw.githubusercontent.com/lavavrik/puppy/main/scripts/install.sh | sh    # Linux, macOS
```

```powershell
irm https://raw.githubusercontent.com/lavavrik/puppy/main/scripts/install.ps1 | iex          # Windows
```

Or pick the archive for your platform below, unpack it and put `puppy` on your `PATH`. Each archive also holds the browser extension (`extension/`), service files (`packaging/`), shell completions (`completions/`) and man pages (`man/man1/`). Step-by-step instructions are in the [README](https://github.com/lavavrik/puppy#install). Checksums are in `SHA256SUMS`.

| Platform | Archive |
|---|---|
| Linux x86_64 | `puppy-0.2.0-x86_64-unknown-linux-gnu.tar.gz` |
| Linux x86_64, static | `puppy-0.2.0-x86_64-unknown-linux-musl.tar.gz` |
| Linux ARM64 | `puppy-0.2.0-aarch64-unknown-linux-gnu.tar.gz` |
| Linux ARM64, static | `puppy-0.2.0-aarch64-unknown-linux-musl.tar.gz` |
| macOS Apple silicon | `puppy-0.2.0-aarch64-apple-darwin.tar.gz` |
| macOS Intel | `puppy-0.2.0-x86_64-apple-darwin.tar.gz` |
| Windows x86_64 | `puppy-0.2.0-x86_64-pc-windows-msvc.zip` |
| Windows ARM64 | `puppy-0.2.0-aarch64-pc-windows-msvc.zip` |

The `-gnu` builds need glibc 2.35 or newer; the static `-musl` builds need nothing, but resolve host names from `/etc/hosts` and DNS only (no mDNS `.local` names). The macOS and Windows binaries are not signed: see the README for the one-time Gatekeeper / SmartScreen step.

## Status

Early development. puppy is used and tested day to day on Linux, and this release is published only after the full test suite passed on every platform. FTP, SFTP and Metalink were also tried against real servers (ftp.gnu.org, OpenSSH, Fedora and openSUSE metalinks), but on macOS and Windows the new protocols, and SFTP's Windows agent support in particular, have seen no real use yet. Bug reports are very welcome.
